## 입력 형식

```
/quality-review [집중 포인트(선택, 자유 텍스트)]
- 집중 포인트 1
- 집중 포인트 2
```

집중 포인트는 인자 뒤 또는 다음 줄 bullet으로 나열. 생략 시 전반적 품질 검사.

## 절차

### 1단계 — 범위 수집

아래 명령으로 현재 브랜치와 변경 범위를 파악한다.

```
git rev-parse --abbrev-ref HEAD
git log main..HEAD --oneline --no-merges
git diff main...HEAD --stat
```

브랜치가 `main`이면 "main 브랜치에서는 실행할 수 없습니다"를 출력하고 종료.

### 2단계 — 집중 포인트 파악

인자와 bullet 목록을 그대로 추출한다. 없으면 "없음 (전반적 품질 검사)".

### 3단계 — 코드 품질 검사 (에이전트 위임)

`oh-my-claudecode:code-reviewer` 에이전트(model=sonnet)에 아래 내용을 포함한 프롬프트로 위임한다.

- `git diff main...HEAD` 전체 diff
- 집중 포인트 목록 — **최우선 검사 대상**
- 검사 범위: 로직 버그, 타입 안전성, 불필요한 복잡도, 테스트 커버리지 공백, 성능 위험
- 금지: 파일 수정, 빌드·테스트·lint 실행

에이전트에게 각 지적사항에 대해 파일 경로·줄번호·내용 한 줄·이유·위험도(높음/중간/낮음)를 반환하도록 요청한다.

### 4단계 — 위험도별 보고서 출력

에이전트 결과를 아래 형식으로 재분류해 출력한다.

```
## 높음 🔴 (즉시 수정 권장)
| 파일:줄번호 | 내용 | 이유 |

## 중간 🟡 (검토 후 결정)
| 파일:줄번호 | 내용 | 이유 |

## 낮음 🟢 (선택적 개선)
| 파일:줄번호 | 내용 | 이유 |
```

해당 위험도에 지적사항이 없으면 해당 섹션 생략.

집중 포인트가 있으면 보고서 상단에 별도 섹션으로 먼저 출력한다.

```
## 집중 포인트 검사 결과
(집중 포인트별 결과 요약)
```

### 5단계 — 다음 단계 안내

보고서 출력 후 아래 안내 문구를 출력하고 종료한다.

> 각 항목에 대해 **'의도한 것'**, **'이런 방향으로 수정해줘'**, **'알아서 수정해줘'** 중 하나로 답변해 주세요.

## 금지

- 사용자 지시 없이 파일 수정
- `git push`, `git commit`
- 빌드·테스트·lint 실행
- confidence가 낮은 추측성 항목 보고
