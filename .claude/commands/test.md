---
description: 컴포넌트 또는 lib 함수의 단위 테스트 작성 (케이스 승인 후 실행)
---

지정한 파일의 단위 테스트를 작성한다. 테스트 케이스 목록을 먼저 제안하고 사용자 승인 후에만 파일을 생성한다.

## 입력 형식

```
/test <파일 경로> [힌트 케이스 (선택)]
```

힌트 케이스는 경로 다음 줄에 bullet로 나열한다. 없으면 Claude가 코드를 읽고 전체 케이스를 제안한다.

## 절차

1. **대상 파일 읽기**
   - 지정한 경로의 파일을 Read 도구로 읽는다.
   - 파일이 없으면 "파일을 찾을 수 없음: <경로>" 출력 후 종료.

2. **기존 테스트 확인**
   - 대상 파일이 컴포넌트(`*.tsx`)이면 같은 폴더의 `__tests__/<파일명>.test.tsx` 존재 여부 확인.
   - 대상 파일이 lib 함수(`*.ts`)이면 `src/lib/__tests__/<파일명>.test.ts` 존재 여부 확인.
   - 기존 테스트가 있으면 내용을 읽어 중복 케이스를 피한다.

3. **케이스 설계·승인·작성** (test-engineer 1회 호출)
   - `oh-my-claudecode:test-engineer` 에이전트에 아래 정보를 전달하고 전체 흐름을 위임한다.
     - 대상 파일 **경로** (내용은 에이전트가 직접 Read)
     - 힌트 케이스 목록 (있는 경우)
     - 저장 경로
     - 아래 "케이스 작성 기준" 전문
   - 에이전트 내부 처리 순서:
     1. 대상 파일 Read → 힌트 케이스 + 코드 분석으로 케이스 목록 도출
     2. `AskUserQuestion`으로 사용자 승인 요청 (`Yes` / `No`)
     3. **No** → "취소합니다." 출력 후 종료
     4. **Yes** → 파일 작성
        - 저장 위치: 컴포넌트(`_components/` 안) → `<컴포넌트 폴더>/__tests__/<파일명>.test.tsx` / lib 함수 → `src/lib/__tests__/<파일명>.test.ts`
        - 기존 테스트 있으면 추가(Edit), 없으면 신규 생성(Write)
        - testing_guide.md 금지 사항 준수 (`Date`/`Math.random` 직접 사용 금지, `console.log` 잔존 금지, 외부 API 실제 호출 금지)

4. **테스트 실행 및 결과 확인**
   - `pnpm test --project unit` 을 run_in_background=false로 실행.
   - 실패 케이스가 있으면 원인 파악 후 즉시 수정, 다시 실행.
   - 전부 통과하면 통과 케이스 수만 한 줄로 출력.

## 케이스 작성 기준

**포함**
- 정상 케이스 (기본 props, 일반 입력)
- 경계값 (빈 배열, null/undefined, 0, 빈 문자열)
- 에러/예외 케이스 (잘못된 입력, 예상 에러)
- 주요 props 조합 (size, variant 등 분기가 있는 경우)

**제외**
- 구현 세부사항 (내부 state 직접 접근)
- 단순 렌더 여부 확인만 하는 케이스 (story 역할)
- 외부 API 실제 호출

## 금지

- 사용자 승인 없이 파일 작성 금지.
- 테스트 통과 전에 완료 선언 금지.
- 관련 없는 파일 수정 금지.
